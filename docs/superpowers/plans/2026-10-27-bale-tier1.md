# bale tier 1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship `bale` tier 1 on macOS, Linux and Windows. It registers agent worktrees, bales idle ones by
removing regenerable build output in place, colds and reopens them, sweeps on a schedule, and migrates the
existing worktrees on this machine.

**Architecture:** A Rust workspace with two crates. `bale-core` is a library holding config, build-system
detection, a file-per-workspace registry, a git wrapper that shells out to `git`, busy/idle probes, and one
module per operation (`up`, `cold`, `open`, `sweep`, `migrate`, `new`, `gc`). `bale-cli` is a thin clap
front end, plus the `hook` and `install` subcommands. All state lives under `$BALE_HOME`, which defaults to
`~/.bale`. Tests override it.

**Tech Stack:** Rust (edition 2021, stable). `clap` 4 (derive), `serde`, `serde_json`, `toml`, `anyhow`,
`thiserror`, `walkdir`, `sha2`, `fs4` (file locks, available space), `dirs`, and `plist` (macOS only). Dev
dependencies: `tempfile`, `assert_cmd`, `predicates`.

**Spec:** `docs/superpowers/specs/2026-10-27-bale-design.md`

**Not in this plan:** the iOS spike and tier 2 (`bale base`, cloning in `bale new`, the `bale-clone` crate).
The iOS spike is a measurement, not code, so it runs on its own before Task 1, as the spec's build order
says. Its result only decides whether iOS gets tier 2. Tier 2 gets its own plan after Task 13, and that
plan's acceptance is the spec's full-day run.

## Global Constraints

- Tier 1 runs on macOS, Linux and Windows; CI runs the full test suite on `macos-latest`, `ubuntu-latest`,
  `windows-latest`.
- Binary name `bale`, built by crate `bale-cli`; library crate `bale-core`. The bare `bale` crate name is
  taken.
- Run the `git` binary, never a git library. Retry on `index.lock` or ref-lock errors with backoff, then
  report. Never delete a lock file.
- Never delete anything while a process has its cwd or an open file in the tree. Busy means skip and
  report, never force. Never stop another session's daemon, Xcode or IDE.
- Never discard uncommitted changes. Never remove a git worktree. Never put bale's commits on a user branch;
  use `refs/bale/<id>/head` and `refs/bale/<id>/wip`.
- `git worktree lock --reason "baled by bale"` before removing anything; unlock only locks with that reason.
- Default idle thresholds: 4 hours to `baled`, 7 days to `cold`.
- Unattended `sweep` never colds a tree with uncommitted changes.
- Saved ignored files: mode 0600, under `$BALE_HOME/<id>/files/`, symlinks saved as symlinks, never in a
  shared store.
- Ignored-file capture uses a denylist (regenerable dirs, `node_modules`, plus the configurable list), never
  an allowlist.
- Regenerable defaults. Gradle: `build/`, `.gradle/`, `.kotlin/`, `.cxx/`, `.externalNativeBuild/`.
  Xcode: the workspace's DerivedData (`.build/` when `-derivedDataPath` points there) and global
  DerivedData whose `info.plist` `WorkspacePath` is inside the workspace. SwiftPM: `.build/`.
- Build systems are detected by marker files: `settings.gradle`, `settings.gradle.kts`, `*.xcodeproj`,
  `*.xcworkspace`, `Package.swift`.
- Config: `<repo>/.bale.toml` overrides `$BALE_HOME/config.toml`.
- Global DerivedData with a missing or unreadable `WorkspacePath`, or matching no registered workspace, is
  never touched.
- `migrate` defaults to a dry run; `--apply` acts; it records free space before and after (not `du`).
- `migrate` reports worktrees under temp directories separately.

## Review Focus

1. **The main checkout is passed to `cold` or picked up by `migrate`.** Expect `cold` to refuse it and
   `migrate` to skip it; deleting a main checkout is unrecoverable. Pinned in Tasks 7 and 10.
2. **A regenerable directory is a symlink** (`build -> /somewhere/else`). Expect only the link to be
   removed, never the target. Pinned in Task 6.
3. **A crash mid-bale** leaves `.bale-trash-*` directories and a record in `Baling`. Expect the next `up` or
   `sweep` to finish the deletion and land on `Baled`. Pinned in Task 6.
4. **Paths with spaces and non-ASCII characters**, which T3 and Claude Code worktree paths can contain.
   Expect every operation to work. Pinned in Tasks 4 and 6.
5. **A worktree directory deleted outside bale** (git shows it as `prunable`). Expect `migrate` and `sweep`
   to report it and carry on, not fail the run. Pinned in Tasks 9 and 10.

### Task 6: `bale up`

**Files:**
- Create: `crates/bale-core/src/ops/up.rs`, `crates/bale-core/src/derived_data.rs`,
  `crates/bale-core/src/ops/mod.rs`
- Modify: `crates/bale-cli/src/main.rs` (add `up <path-or-id>` and `ls`)
- Test: `crates/bale-core/tests/up.rs`

**Interfaces:**
- Consumes: Tasks 1–5.
- Produces:
  - `pub enum Outcome { Done(Level), Busy(Vec<Holder>), Skipped(String) }`
  - `pub fn register(home: &BaleHome, path: &Path) -> Result<Record>`. It creates or refreshes a `Hot`
    record from git, and errors when the path is the main checkout.
  - `pub fn up(home: &BaleHome, id: &str) -> Result<Outcome>`
  - `pub fn derived_data_for(workspace: &Path, dd_root: &Path) -> Vec<PathBuf>`. It returns DerivedData
    folders whose `info.plist` `WorkspacePath` starts with `workspace`. It is compiled on all OSes so it can
    be tested; `dd_root` is `~/Library/Developer/Xcode/DerivedData` on macOS only.
- Algorithm (fixed by the spec's step list):
  1. Acquire the lock; if it is held, return `Skipped("locked")`.
  2. If `busy_holders` is non-empty, return `Busy`.
  3. `lock_worktree`.
  4. Save the record as `Baling`.
  5. Rename each regenerable dir to `<parent>/.bale-trash-<name>-<nanos>`. If a rename fails with
     permission denied or a sharing violation, rename the already-moved ones back, unlock, save as `Hot`,
     and return `Busy(vec![])`.
  6. Remove every `.bale-trash-*` under the root. Use `remove_dir_all`; for symlinks, `remove_file` on the
     link.
  7. On macOS, remove `derived_data_for` matches.
  8. Save as `Baled`.

  At step 0, if the record is already `Baling`, skip straight to step 6. That is the crash recovery path.

### Task 7: `bale cold`

**Interfaces:**
- Consumes: `up` (Task 6), `Git` (Task 4).
- Produces:
  - `pub fn cold(home: &BaleHome, id: &str) -> Result<Outcome>`
  - `pub fn save_wip(dir: &Path, id: &str) -> Result<()>`. It writes `refs/bale/<id>/head` (HEAD) and
    `refs/bale/<id>/wip`, a commit whose tree is HEAD plus tracked changes plus untracked non-ignored files,
    with parent HEAD. It uses a temporary `GIT_INDEX_FILE`, then `read-tree HEAD`, `add -A`, `write-tree`
    and `commit-tree`. It never touches the real index.
  - `pub struct SavedFile { pub rel: PathBuf, pub sha256: String, pub symlink_target: Option<PathBuf> }`

    directories, walks the rest, copies files with mode 0600 (on unix) and recreates symlinks. It writes
    `manifest.json`.
- Order: run `up` first (it must return `Done(Baled)`). Then:
  1. Refuse if this is the main checkout, if `core.sparseCheckout` is true, or if any submodule is dirty
     (`git submodule foreach --quiet 'git status --porcelain'` produces output).
  2. Save the record as `Cooling`.
  3. `save_wip`.
  4. `save_ignored`.
  5. Verify every manifest hash against the tree.
  6. Rename the worktree dir to `<parent>/.bale-trash-<name>-<nanos>`, then remove it.
  7. Save as `Cold`.

### Task 8: `bale open`

**Files:**
- Create: `crates/bale-core/src/ops/open.rs`
- Modify: `crates/bale-cli/src/main.rs` (add `open <path-or-id>`)
- Test: `crates/bale-core/tests/open.rs`

**Interfaces:**
- Consumes: `Record.admin_dir` and `Record.branch` (Task 3), `SavedFile` and the manifest (Task 7).
- Produces: `pub fn open(home: &BaleHome, id: &str) -> Result<OpenReport>`, where
  `pub struct OpenReport { pub detached_reason: Option<String> }`.
- Algorithm:
  1. Create `path`.
  2. Write `path/.git` as `gitdir: <admin_dir>`.
  3. `git read-tree -u --reset refs/bale/<id>/wip`, then `git reset -q refs/bale/<id>/head`. This leaves
     changes unstaged and untracked files untracked.
  4. Restore the saved files and verify their hashes.
  5. If `branch` is set, its ref equals `head`, and no other worktree has it checked out, run

**Interfaces:**
- Consumes: `new_workspace`, `cold`, `register`.
- Produces:
  - `bale hook claude-worktree-create`. It reads the JSON payload on stdin, calls `new_workspace`, and
    prints only the absolute path followed by `\n` on stdout. All logs go to stderr. If `new_workspace`
    fails, it runs a plain `git worktree add` and prints that path.
  - `bale hook claude-worktree-remove`. It reads the JSON on stdin and calls `cold`. It exits 0 only when the
    worktree dir no longer exists afterwards. Busy or dirty-refused cases exit non-zero with the reason on
    stderr.
  - `bale hook git-post-checkout <prev> <new> <flag>`. When `prev` is all zeros and `flag` is `1`, and the
    cwd is a linked worktree, it calls `register`. It always exits 0, so it never fails a checkout.
  - `bale install` writes the sweep schedule (every 30 minutes, running `bale sweep`):
    - macOS: `~/Library/LaunchAgents/dev.bale.sweep.plist` with `StartInterval` 1800, then
      `launchctl bootstrap gui/<uid>`.
    - Linux: `~/.config/systemd/user/bale-sweep.{service,timer}` with `OnUnitActiveSec=30min`, then
      `systemctl --user enable --now bale-sweep.timer`.
    - Windows: `schtasks /Create /SC MINUTE /MO 30 /TN bale-sweep /TR "bale sweep" /F`.
  - `bale install --hooks claude` adds `WorktreeCreate` and `WorktreeRemove` command hooks to
    `~/.claude/settings.json`, preserving existing keys and printing a diff first. `--hooks git --repo <repo>`
    installs a `post-checkout` that calls `bale hook git-post-checkout "$@"`, then runs the previous hook.
